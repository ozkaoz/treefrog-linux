## Diagnóstico (evidencia)

1. `cubevol` (daemon input stock, /usr/bin/cubevol del rootfs stock preservado en la SD):
   `strings` → abre `/dev/input/js0..3` + `/proc/bus/input/devices`; escribe `/tmp/joy_key`
   que picoarch/FrogUI leen (zhijack: "keeping the cubevol gpio -> /tmp/joy_key input pipeline up").
2. `/dev/input/jsN` lo crea el módulo **joydev** (`CONFIG_INPUT_JOYDEV`).
3. Nuestro config (kernel-squashfs.config base del SDK): `# CONFIG_INPUT_JOYDEV is not set`.
4. **Kernel stock**: `strings vmlinux.stock.elf` → `joydev: failed to reserve new minor`,
   `&joydev->mutex`, `Joystick` → joydev compilado built-in.
5. Drivers hc_key_adc/hc_gpio_key SÍ estaban en nuestro kernel (System.map) — el ADC/keys
   registra dispositivos input, pero sin joydev no hay nodo /dev/input/jsN para cubevol.

Conclusión: **única diferencia funcional detectada entre stock y nuestro kernel = joydev**.

## Fix aplicado

`boards/r36sx/config/r36sx.fragment.config`:
```
CONFIG_INPUT_JOYDEV=y
```
build-kernel.sh ahora aplica el fragment vía `scripts/kconfig/merge_config.sh` + verificación
post-olddefconfig (fragment confirmado activo en el build #2).
